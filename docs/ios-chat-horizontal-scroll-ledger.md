# iOS Chat 横向滚动修复记录

## 当前状态

修复、本地回归和生产部署已经完成。问题已由用户提供的 iOS 实机截图确认。斜向上下滑动 Chat 消息列表时，消息内容会整体向左或向右回弹，露出视口外区域。当前机器没有 iOS 实机或模拟器，仍需进行最终真机复测。

## 已确认事实

- Chat 外层和应用主区域已经限制宽度，当前移动视口下它们的宽度与页面宽度一致。
- `.chat-timeline-scroll` 只声明了纵向自动滚动。浏览器计算后的横向滚动仍为 `auto`，横向回弹策略也为默认值。
- 当前消息列表没有真实的横向溢出，`clientWidth` 与 `scrollWidth` 均为 393 像素，因此横向位移来自滚动容器的边界回弹，不是消息列表需要横向滚动。
- 代码块和表格拥有各自的横向滚动容器，不能通过禁用所有横向触摸来处理外层问题。

## 失败证据

- `.cohub/relay-attachments/375e3e63-8e23-4185-b325-88690826ca68/IMG_0261.jpg` 显示消息列表向右回弹。
- `.cohub/relay-attachments/35bb12e2-0273-4355-a4be-4267ae7db71c/IMG_0260.jpg` 显示消息列表向左回弹。
- 共享浏览器移动视口检查显示消息列表的 `overflow-x` 和 `overscroll-behavior-x` 都处于允许横向回弹的默认状态。

## 决策

只关闭消息列表外层的横向滚动和边界回弹，不在应用根层禁用横向手势。这样可以保留左右侧栏的边缘滑动，也不会影响代码块、表格和图表自己的横向操作。

## 已完成工作

- Chat 消息列表明确设置为只允许纵向滚动，并关闭外层横向边界回弹。
- 消息列表补充最小宽度约束，避免长内容扩大外层滚动区域。
- 新增定向回归，验证外层横向锁定，同时验证代码块和表格仍保留自己的横向滚动。

## 验证证据

- 定向测试修复前失败，修复后两项通过。
- Web 前端完整测试共 401 项通过。
- 本地移动视口检查显示消息列表从 `overflow-x: auto` 变为 `hidden`，纵向仍为 `auto`。
- 同一检查确认应用主区域的侧栏手势仍为纵向页面手势加自定义边缘滑动，代码块和表格仍允许局部横向滚动。
- 共享浏览器移动触摸检查分别从左右屏幕边缘完成滑动，两侧抽屉都从隐藏状态移动到 `translateX(0px)` 并恢复交互，证明边缘手势路径未被本次修改切断。
- 共享浏览器对消息列表执行带横向偏移的斜向上滑，纵向位置从 500 移到 785，横向位置保持为 0，证明横向锁定没有破坏上下滚动。
- 改动文件格式检查和差异检查通过。
- 全量类型检查运行到结束，只有两个与本次改动无关的既有测试类型错误，改动文件没有报错。
- 当前机器没有 Xcode、iOS Simulator 或连接中的 iPhone，浏览器移动视口检查不能代替 iOS 最终证据。
- 修复已随提交 `73ecfa2a5b9f66a38905478814aea3cd2845f36a` 发布到生产 Worker 版本 `4e895ea4-01d1-4df6-9251-d82fba115e91`。
- 生产页面绕过缓存重载后，393 像素移动视口没有页面级横向溢出。斜向上滑使纵向位置从 500 移到 683，横向位置保持为 0；左右抽屉边缘滑动和代码块局部横滑仍然有效。桌面 1440×900 视口也没有页面级横向溢出。

## 下一步

部署后在 iOS standalone PWA 中执行缓慢斜滑、快速连续滑动、代码块横滑、表格横滑、左右侧栏开合和键盘开合后的滚动，确认页面不再左右漂移且局部手势无回归。
