# 本地空间自动运行台账

## 目标

让界面中新建的每个本地 Space 自动获得隔离的工作目录与可用执行入口，无需手动运行 CLI；Codex、Grok Build 和 Pi 均可完成首次对话与续聊，并能在服务或 Mac mini 重启后恢复。

## 修复前事实

- 2026-08-24，新建空白 Space `d5bb1cb3-2154-4037-944f-554e83200df5` 已创建数据库记录与 `~/.cohub-local-mode/spaces/<spaceId>/workspace` 目录。
- 该 Space 没有本地 sandbox runner。Agent 等待约 60 秒后以 `sandbox is not ready for requests yet: missing endpoint` 失败，日志 trace 为 `671fec09a310059eb1d56eebee3e3ff9`。
- 当前 Local Mode 主服务不会发现新建 Space 并启动 runner。文档仍要求用户另开终端执行 `cohub sandbox up`，与本目标冲突。
- 现有手动 runner 只绑定单个旧 Space，不能覆盖后续新建 Space。

## 已确认决策

- Local Mode 主服务负责监督自动管理的本地 runner；每个本地 Space 使用 `SPACE_STORAGE_ROOT/<spaceId>/workspace`，不得共享目录。
- 复用现有 sandboxd 与 gateway relay，不另写文件或命令执行协议。
- 自动 runner 使用仅在本地节点进程内派生的专用 relay 凭据，不依赖用户浏览器令牌，也不向公网开放新端口。
- 活跃的手动 runner 可继续接管同一 Space；自动管理提供无需 CLI 的默认可用路径。

- 修复前真实失败已保留在 `~/.cohub-local-mode/logs/host.stdout.log`，Space 与报错内容和用户截图一致。

- 用户截图中的原始失败 Space `d5bb1cb3-2154-4037-944f-554e83200df5` 也已由 supervisor 自动恢复；在最终服务重启后发起 Pi 首轮对话，9.9 秒完成并写入预期文件，不再出现 `missing endpoint`。
- 同一验收 Space 内，Codex 使用 `gpt-5.6-luna/low`、Grok Build 使用 `grok-4.6/high`、Pi 使用 `claude-sonnet-4-6/low`，首次对话和第二次续聊均完成。三个 Agent 分别写入独立标记文件，文件内容与对话轮次一致。
- 验收 Space 的标记文件没有出现在 `d5bb1cb3-2154-4037-944f-554e83200df5` 或手动工作目录中，证明 Space 目录隔离有效。
- Codex Session 尝试切换为 Pi 时，接口以 `409 agent harness is locked after the first turn` 拒绝，没有创建错误执行。
- 主机服务重启后，验收 Space、原始失败 Space 与手动接管 Space 均恢复。手动 runner 重新连入后，自动 runner 收到 `replaced by new runner` 并退出，没有持续争抢。

- API 的本地专用凭据只在 local node 精确匹配时生效；错误凭据、空凭据和 cloud node 均被拒绝。Agent 只把 supervisor 的真实失败转换为快速明确错误，不改写普通 provisioning 或 cloud 错误。
