桌面子进程不继承三个 TALESOFAI_BILLING 托管配置项，真实子进程环境测试通过。复用现有 disabled billing provider，不修改云端计费和云端授权。billing、core、SDK、CLI、worker、agent、gateway 构建通过，API 完整类型检查通过，打包不再使用 --noCheck。

## 续作中的真实连接与文件验证

2026-09-06 续作，没有重新要求 Gitea 登录，没有操作生产或旧 dev。此前的 0.3.0-dev2.1 安装包不包含本节修复，不能把源码运行证据套用到旧包。

Web 原先等 API 启动后才加载，实际发生 API 已就绪而 Web 连接超时。现并行加载 Web 与 API，仍要求 Web、API、Gateway 都通过健康检查后才报告 ready。前两次实测约 43 秒，之后一次 API 在高负载下超时，后续启动分别约 51 秒和 73 秒，不能宣称启动耗时已经稳定。现场曾记录 16 GiB 内存、约 11.77 GiB swap 使用和约 24 的 load average；没有停止其他用户进程来制造性能结果。

共享 Chrome 完成了真实客户端设备码授权。实测 Electron 内 Node fetch 连续请求出现超时，而同进程 Chromium net.fetch 四次均成功；客户端云端鉴权改用 Electron 网络栈，禁止跨源及重定向携带凭据，设备码轮询遇到临时网络错误会在原有效期内继续，不反复产生授权码。

真实登记曾出现服务端已创建设备、客户端收到响应前超时，随后丢失设备身份。现在先在 Dev2 专属 Keychain 保存凭据，再保存无密钥的 pending-registration.json，后续登记失败复用身份。已有身份缺凭据、跨账号与损坏 pending 状态都明确失败。3 项测试通过，证据为 registration-retry-red.log 和 registration-retry-green.log。此前仅由本次测试产生、从未连接的孤立设备 7ce344c3-c37c-441d-9464-e82de4c7193c 已经核对安装 ID 和创建时间后撤销，没有撤销其他设备。

隔离 HOME 缺少 macOS 默认 Keychain，导致第一次真实保存失败。仅 Keychain 子进程改用操作系统登录用户的 HOME，其余运行环境保持隔离，服务名仍为 Cohub Dev2 Personal Node / Cohub Dev2 Cloud Auth。没有修改默认钥匙串或生产服务。真实 Dev2 设备 e842e949-3b75-404b-bdd0-e5f6b792dc07 已完成登记，并在后续重启复用同一身份。桌面未登录时不能再回退到宿主机 CLI 的其他身份，相关 5 项测试通过，API 完整编译通过。

首次握手真实失败于节点 ID 不一致：桌面传设备 UUID，云端返回账号与设备共同计算的哈希。现与服务端的 alphaNodeId 契约一致，同时校验子进程 PID，未删除身份校验。与实际服务端函数对照的测试先失败后通过；connector-core 共 6 项测试通过。修复后客户端与 Dev2 服务端均报告 connected，实际请求已经往返，不只是 socket open。另修复 Node relay 对 204/205/304 非法构造响应 body 的问题，真实 HTTP 服务测试先失败后通过。
