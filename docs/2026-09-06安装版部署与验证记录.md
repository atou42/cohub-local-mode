## 已取得的证据

Gitea 登录态已生效。原私有 SDK 的 API 下载路径不接受网页会话，改用包页面返回的文件下载链接后取得真实的 1.16.0 包，42754 字节，SHA-512 与原锁文件完全一致。通过短时 loopback 下载桥交给 pnpm 自己建立缓存，随后离线冻结锁文件安装。没有伪造依赖、类型声明、令牌或修改锁定版本。下载桥已关闭，网页 cookie 没有写入文件。

桌面子进程不继承三个 TALESOFAI_BILLING 托管配置项，真实子进程环境测试通过。复用现有 disabled billing provider，不修改云端计费和云端授权。billing、core、SDK、CLI、worker、agent、gateway 构建通过，API 完整类型检查通过，打包不再使用 --noCheck。

运行环境依赖打包成功。移除了过时的可选 SDK 悬空链接清理逻辑，它将真实已安装的 SDK 目录错误地当成非法链接，曾导致打包失败。完整归档为 1072586752 字节，修正 manager 后 SHA-256 为 65786cc2a13e742cf4721dbe31bd9e750faab047111de441a28799071a89d55b。打包后逐个核对 PostgreSQL 的 17 个动态库符号链接，全部指向存在的原文件。PostgreSQL 18.4 和 Valkey 9.1.2 的真实二进制可以执行。

首次隔离启动真实失败于 PostgreSQL Unix socket 路径超长。所有使用方原本已走带密码的 loopback TCP，现关闭不使用的 Unix socket，不缩短测试目录来掩盖故障。修复后新目录首次启动 58.1 秒，实际首页 200、30120 字节，样式 200；缺少桌面实例密钥返回 403，缺少云端身份返回 401。进程正常退出，退出码 0。

在独立测试数据库写入唯一标记，同时写入测试 Space 文件。再次启动后数据库内容、文件字节和 runtime-state 的摘要保持一致。Node 启动实测 45.7 秒；切换到安装器内的 Electron 44.1.1 引擎后实测 105.9 秒，同样通过实际页面、鉴权失败和持久化检查。以上是本机负载下的样本，不代表启动体验已经达到目标，也不等于旧版真实用户数据迁移验收。

启动清理修复已整合本地提交 260ce8a6。13 个启动和 connector 测试通过，包括身份验证失败、迟到 ready、超时、提前退出、清理失败，以及真实临时 Node 进程终止。新增 helper 不存在导致的编译失败不作为原缺陷的行为复现证据。运行环境另有 5 项测试通过，包含拒绝不属于客户端的健康 API、不修改既有状态、HTTP/WebSocket 实例保护和明确的 API 失败。

Web 类型检查发现 alpha 集成时重复写入测试 fixture 的 agentHarness，删除后来添加的重复项，保留原生产值；重新检查为 0 error、0 warning，9 项相关 overview 测试通过。远程 HTTP 204 响应被错误地用空字符串创建 Response，已取得失败测试并修复；204、205、304 保留真正的 null body，非法非空 body 仍报错，10 项相关测试通过。

Dev2 发布顺序改为先建立 Web Custom Domain，再部署同域名下的 relay 路由，发布测试先失败后通过。第一次真实 Cloudflare 构建还暴露出 adapter 会覆盖配置中的 main 文件。已将 adapter 输出与手写部署 wrapper 分开，避免丢失旧静态资源请求失败时的 no-store 保护。修复后的完整构建与两个 Worker 的 dry-run 均退出 0，手写 wrapper 未再被覆盖。

已建立 dev2 独立队列 cohub-personal-node-dev2-wakeups、R2 cohub-personal-node-dev2-attachments、Web Worker 和 relay Worker。Relay 发布版本为 b142cf54-cade-46f0-bf38-777e95ba15d4。根入口原先显示生产营销页面，随后实测又发现旧安装版 /spaces 入口已不存在；已统一转向生产已有的 /sessions，并为根入口配置 Worker 优先于静态资源处理。Web 最终版本为 d04879a3-a704-4a80-9163-41cf592befc3，真实根路径请求返回 302，Location 为 https://dev2-cohub.atou.cc/sessions。最终资源保护与发布测试共 10 项通过，发布命令退出 0。
