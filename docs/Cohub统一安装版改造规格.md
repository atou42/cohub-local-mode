# Cohub 统一安装版改造规格

本文为 2026-09-05 已有文档的审阅副本，保留原时点判断。当前实现与修复状态以 [现状、目标与问题](./Cohub安装版现状、目标与问题.md) 为准。用户于 2026-09-06 新增授权将当前安装版独立分支提交 GitHub，供 ChatGPT Pro 咨询；不包含合并 main、部署生产或更换客户端。历史本地日志与截图未公开，不可作为审阅方已亲自验证的证据。

2026-09-05，用户已确认并明确将本轮部署测试域名改为 dev2-cohub.atou.cc。3 级。本轮从只读审视进入实现，涉及连接身份、执行一致性、旧数据兼容和未来生产替换。生产及原 dev 环境均保留不动。

## 目标

把安装版做成我们现有 Cohub 的下一代交付方式，而不是功能缩水、长期独立维护的另一个产品。自己的生产版本是能力基线：普通用户安装后使用本机能力，无需配置 Cloudflare；同机交互不依赖云端中转，手机和异地访问继续可用。最终目标是有条件地替换 cohub.atou.cc，但本轮先交付经过验证的候选版本，不直接切换生产。

## 基线

本轮已重新读取 GitHub，`atou42/cohub-local-mode` 的远端 main 为 `1d08c8ddb48e87af609de2639334b2be62590d6e`。当前监听本机 API 的进程工作目录位于 `1545658927302058035/cohub-rebase/apps/api`，该生产目录 HEAD 与上述提交一致。安装版来自同仓库的 `feat/cloudflare-personal-node-alpha`，HEAD 为 `f9e17c1609fc0e5642a05f2466194ea762939be4`。安装版原工作树的本地 main 仍停在较旧提交，不能拿它代替已核实的远端和生产基线。

业务对齐对象是自己的生产 main；`talesofai/cohub` 仍是源项目上游，不更改 Git remote 含义。新工作在本线程独立目录、独立分支进行，从锁定的生产 main 出发，核对并接入安装版必要差异，避免用旧 alpha 整体覆盖生产能力。保留两个原工作区、历史和未提交内容。候选版本交付及未来合入前重查生产 main；若前进，核对新增差异，不以今天的基线永久冻结产品能力。

## 范围

先把生产已有能力及 alpha 特有能力对应到代码、现有验收证据和本轮检查。范围覆盖 Local 与 Cloud Space、原有会话及恢复、Pi/Codex/Grok Build/Cursor 接入、模型与执行设置、文件与附件、跨 Space 操作、生成及作品、已有应用和定时活动，以及相关 Web、SDK、CLI 行为。沿用生产已有的权限和外部服务条件；能力不能因为安装方式变化被删除、隐藏或替换成占位。能力对照用于防遗漏，不是另建产品路线图。

优先修复审视报告中的结果确认缺陷、错误本机实例接入、超时与重复执行问题。为本机客户端建立受认证和实例归属约束的直接访问路径，复用现有业务和界面，后台任务不随窗口关闭结束。异地访问保留云端账号与设备管理，但页面读取不再与全部操作共用整机串行队列；同时修复设备选择、连接状态、缓存刷新和内容保留边界。停网验证只隔离测试进程的云端通路，不中断整台机器或生产网络。

保留当前运行底座，按实际启动耗时减少非必要阻塞，不先更换 Electron、数据库或重写业务服务。补齐安装、启动、诊断、版本兼容与旧数据升级恢复路径，先以当前 macOS ARM64 为可交付平台。程序升级不得重建用户身份、工作区、原生执行器会话或文件目录来制造成功。普通用户的首次可用路径必须明确区分应用已安装、执行器可用、模型已授权。

续作中用户明确本地不需要计费。桌面运行环境不启用 Cohub 托管计费，不继承宿主机的托管计费凭据；复用现有 disabled billing 行为，不伪造余额或放宽云端授权。云端服务、模型供应商和生产版原有计费保持不变。构建时保留生产能力所需的真实依赖，不要求终端用户自行配置计费服务。

允许本机隔离实现、构建、测试、自有测试进程启停和 dev2-cohub.atou.cc 独立开发资源发布。只为 dev2 创建和配置所需域名路由及独立 Worker、存储、队列、设备和测试数据；不得复用生产或原 dev 的可写绑定。开发版用户可见的变化只在 dev2 验证，cohub.atou.cc 和 dev-cohub.atou.cc 的进程、数据、Cloudflare 资源及访问范围保持不变。安装与恢复演练使用独立测试目录和旧版样本，不把生产数据上传到开发环境；真实设备上更换用户正在使用的客户端另行确认。

## 不做什么

本轮不推送远端分支、不创建或合并 PR、不改 main、不部署或替换 cohub.atou.cc 或 dev-cohub.atou.cc，不修改两者的 DNS 或访问权限。仅允许为用户指定的新 dev2 域名建立独立路由。未来替换的含义是升级同一个产品，绝不包含公开现有个人数据。正式切换时，基于已验收候选版本另行确认数据备份、恢复、兼容旧客户端和切换范围；不能把回退程序版本当作已经证明数据可以恢复。

不扩展 Windows/Linux，不新增多人共享或全量文件同步，不更改计费产品，不购买证书、开通付费服务或伪造缺失凭据。不做与本次对齐和可靠运行无关的重构。若签名、公证、私有依赖或真实推理验证缺少合法条件，明确保留为未完成项，不降低验收标准。

## 交付物

交付与生产能力对齐的本地候选分支、可验证的 macOS 安装产物和开发版，附能力对应与验证记录、已知限制及生产替换所需的恢复说明。验证记录必须区分源码检查、自动测试、真实运行和仍缺证据的部分。未完成签名或首次使用验证的安装包只能标为测试包，不能标为正式发行版。

## 验收标准

结果确认问题先以真实消息顺序看到失败，再修复并通过；正常执行、迟到结果、重复请求、取消和断线恢复必须证明结果没有丢失、写操作没有额外发生。本机可用但云端中转不可达时，仍能打开本机工作区、历史、文件并管理本机执行；需要联网的模型服务按真实条件显示可用性，不假称完全离线推理。远程路径必须覆盖桌面和手机真实操作，不能用健康接口或缓存首屏代替执行成功。

生产能力对照中的每项都有保留依据；受影响的主要路径必须实跑，已有可靠证据只复用未受影响的部分。旧版本样本升级后身份、会话关联、文件内容和既有访问关系保持一致；恢复演练能回到一致状态。错误实例、坏缓存、损坏状态或凭据错误必须明确失败，不能清空重建或静默换设备继续。安装产物必须在非生产测试环境完成启动与代表性任务，隔离测试通过不冒充用户实际 MacBook 已验收。

实现稳定后做一次与风险匹配的最终验收，失败后只重跑受影响部分。达到本轮验收是生产替换候选资格，不是已经获准替换；正式替换还需核对当时的生产增量、真实数据恢复和旧客户端兼容证据。

## 失败判据

任何生产既有能力丢失、会话或文件关联变化、结果丢失或重复写入、身份与权限误接、无法安装启动、远程路径不可用、恢复失败，都阻止候选版本通过。外部条件不足标为未完成，不能标成通过；发现必须改变目标结构或删减能力才能继续时，提交具体范围变更并等待确认，不自行改验收。
