# Cohub 安装版现状、目标与问题

记录日期：2026-09-06。本文整理已确认的目标与截至本轮的实现、实测结果，供后续开发接续。运行状态是测试时的快照，不代表持续可用承诺。

## 当前结论

Dev2 开发环境已经部署，macOS ARM64 测试安装包已经生成。本机与 Dev2 网页之间的真实文件读写、正常重启后的测试身份与文件保留，以及同一已完成命令的重复提交检查均已通过。

当前版本尚未取得生产替换候选资格，也不能作为正式安装器分发。首次安装与升级过慢，启动超时恢复后不打开窗口；断网、崩溃恢复和完整生产能力保留仍未完成验收。不能把网站能打开、设备 connected 或单条文件测试通过等同于整个产品可用。

## 产品目标

安装版应当成为现有 Cohub 的下一代交付方式，而不是功能缩水、长期独立维护的另一个产品。能力基线是我们自己的 `cohub.atou.cc` 生产版本。达到完整验收后，才考虑用安装版替换生产；当前只在 `dev2-cohub.atou.cc` 部署和测试。

普通用户安装客户端即可获得本机运行能力，不需要自行配置 Cloudflare。本机界面访问本机服务，不依赖云端中转；手机和异地访问通过统一账号与设备中转使用本机能力。云端不可达时，本地工作区、历史、文件和本机执行管理仍应可用；需要联网的模型服务必须如实显示状态，不承诺离线推理。

本地运行不启用 Cohub 托管计费，也不继承宿主机的托管计费凭据。模型供应商费用、云端授权和生产原有计费不在此次修改范围内。首次使用必须区分应用已安装、执行器可用、模型已授权，不能让用户装完才发现还缺少未说明的运行条件。

生产已有的 Local / Cloud Space、会话及恢复、Pi / Codex / Grok Build / Cursor 接入、模型与执行设置、文件附件、跨 Space 操作、生成及作品、应用、定时活动和相关 Web / SDK / CLI 行为均属于保留范围。升级不能重建用户身份、清空数据或丢失执行器会话关联来制造成功。

## 已完成与证据边界

真实私有依赖已取得并核对锁定摘要，构建不再依赖伪造包或跳过 API 类型检查。本地托管计费配置已隔离。PostgreSQL 首次启动路径问题、安装重试临时目录冲突、解包期间退出与迟到启动等缺陷已修复，并保留失败与回归记录。Web 与 API 现在并行启动，但仍要通过实际就绪检查。

客户端云端鉴权改用经过实测的 Electron 网络栈。设备登记失败后复用已保存的身份和凭据，不因响应丢失重复生成设备。Keychain 与隔离 HOME 的兼容问题、桌面未登录时误回退到宿主机 CLI 身份，以及客户端与云端节点 ID 不一致的握手问题已经修复。没有删除实例归属或身份校验。

全新安装原先会把整个本地数据目录误设为只读，导致工作区无法写文件。技能兜底目录已移到独立配置路径，旧技能内容通过目录迁移保留；存在冲突时明确失败，不覆盖内容。HTTP 204 / 205 / 304 的空响应处理也已修复。

真实文件测试使用独立测试 Space。本机写文件后，Dev2 读取到逐字一致的内容；Dev2 修改后，本机读取一致。重复提交相同幂等键返回原命令、attempt 仍为 1，没有再次执行。远端尝试读取本机鉴权接口被 403 拒绝。桌面与手机视口均显示了该文件。

新包正常重启后，原测试设备身份仍在，测试文件的磁盘字节与本地 API 内容一致。再次提交升级前的同一写入请求，仍返回原命令，文件修改时间未变化。这只证明该测试身份、文件和已完成命令在正常重启中保留，不证明全部生产数据迁移、全部功能保留或崩溃中的结果恢复。以上文件测试没有提交模型推理请求。

## 已知问题与未完成项

### 安装和启动耗时

实际新包首次升级到连接成功共 965.4 秒，超过 16 分钟。其中归档校验约 49 秒，解包约 680 秒，随后又遇到后端 120 秒启动超时。正常关闭后再次启动仍需 131.8 秒，其中约 34 秒用于归档校验。

当前运行归档约 1.07 GB，包含 82296 个 tar 条目。测试机器当时有较高内存、交换空间和文件系统压力，但尚未证明具体瓶颈。不能据此把问题归咎于机器，也不能只放宽超时就宣称安装体验达标。

### 恢复后没有窗口

首次启动超时后，后台自动恢复并成功连接，但最初失败的打开窗口流程没有再次执行，实际没有页面。用户可能面对后台已运行、客户端却没有可操作界面的状态。手动关闭再启动能打开窗口只是诊断结果，不是修复。

启动中仍出现短暂状态上报和 Sandbox 超时。退出过程中也曾出现 stopped 之后的迟到连接状态。启动、恢复、停止和界面状态尚未形成可靠的一致行为。

### 断网与崩溃恢复

离线且云端身份过期时的本地可用性仍需处理和实测。网络恢复后，连接、未完成请求和界面状态能否正确恢复，尚未完成验收。

结果持久化与确认链路仍需覆盖执行后进程崩溃、结果未被确认、重连和重试等情况。当前缺少完整的持久待发送结果机制及相应证据。一次已完成命令的幂等测试，不能证明断线或崩溃期间不会丢结果、不会重复写入。

### 身份、设备与缓存隔离

登记重试与凭据问题已经修复，但设备选择和账户缓存隔离仍未完成。需要证明切换账号、设备失联、缓存过期或状态损坏时，不会误接其他设备、展示错误账号的数据，或通过静默重建状态继续运行。

### 完整能力与升级保留

目前没有完成生产能力逐项验收。文件链路通过不代表聊天执行、执行器会话恢复、模型首次配置、附件、跨 Space 操作、应用及定时活动都可用。

旧版本完整升级、失败后的数据恢复、会话关联与访问关系保留仍缺少覆盖。不能用空白安装、单个测试文件或回退程序版本替代完整的数据恢复证明。

### 界面与正式分发

实际窗口仍存在长工作区标题挤成多行、vConsole 可见的问题。远端文件虽然可以展示，截图中的工作区导航并未完整加载。当前视觉证据只证明文件预览，不代表完整使用体验优秀。

正式签名、公证和新用户首次使用验收尚未完成。当前仅覆盖 macOS ARM64，不扩展为 Windows / Linux 交付承诺。

## 后续处理与完成条件

已知首次安装耗时和恢复后不打开窗口，应先取得针对性诊断与修复证据。后续必须补齐断网及崩溃结果恢复、账号与设备隔离、真实旧版升级保留，再完成生产能力对照与代表性任务验收。这些是现有目标中的未完成项，不是新增功能范围。

通过条件不是最后出现 connected，而是安装后有可操作界面，本机与异地主要路径真实可用，失败状态明确，重试不产生额外写入，升级与恢复不丢身份、会话关联和文件。完整规格通过后，也只是取得生产替换候选资格；正式切换仍需核对当时的 main、备份恢复与旧客户端兼容条件。
